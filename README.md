# TESR Chat — ระบบรวมแชตของ TESR

รวมแชตลูกค้าจากทุกช่องทางไว้ในหน้าเว็บเดียว ทีมตอบได้จากที่เดียว และหัวหน้าดูได้ว่าใครตอบ ตอบเร็วแค่ไหน

**ใช้งานได้แล้ว:** LINE OA · Facebook Messenger · Instagram DM · หน้า Inbox · ระบบพนักงาน · โน้ต · ฝ่าย · ผู้ดูแล · เวลาตอบ · Dashboard · Export CSV · **หน้าตั้งค่าแอดมิน** (เชื่อมทุกช่องทางจากหน้าเว็บ)
**เฟสถัดไป:** TikTok, YouTube (คอมเมนต์), Shopee, Lazada — หน้าตั้งค่าและฐานข้อมูลรองรับไว้แล้ว

## ขั้นตอนติดตั้ง (ทำครั้งเดียว ใช้เวลาประมาณ 20–30 นาที)

ส่วนที่ต้องทำนอกระบบมีแค่ **Supabase + GitHub** ส่วนการเชื่อม LINE, Facebook, IG และช่องทางอื่น ๆ ทำได้ใน **หน้าเว็บ > ⚙ ตั้งค่า** ซึ่งมีขั้นตอนบอกทีละข้อพร้อมช่องให้กรอก

### 1) สร้าง Supabase
1. สมัครที่ https://supabase.com แล้วกด **New project** (เลือก Region: **Southeast Asia (Singapore)**)
2. ไปที่ **SQL Editor > New query** วางไฟล์ `supabase/schema.sql` ทั้งไฟล์ แล้วกด **Run**
3. ไปที่ **Project Settings > API** แล้วจด `Project URL` (ส่วน `xxxx` ใน `https://xxxx.supabase.co` คือ **Project Ref**) และ `anon public` key
4. ไปที่ **Authentication > Sign In / Providers** แล้วปิด **Allow new users to sign up**
5. สร้างบัญชีแรกที่ **Authentication > Users > Add user** (ติ๊ก **Auto Confirm User**)
   → **บัญชีแรกจะเป็นแอดมินอัตโนมัติ** ส่วนพนักงานคนอื่นค่อยเพิ่มจากหน้าเว็บ
6. สร้าง Access Token สำหรับ GitHub: ที่มุมขวาบนกด **Account > Access Tokens > Generate new token**

### 2) GitHub
1. **เปิดใช้ workflow (ทำครั้งเดียว):** คัดลอกไฟล์ 3 ไฟล์ในโฟลเดอร์ `setup/github-workflows/` ไปไว้ที่ `.github/workflows/`
   - บนเว็บ GitHub: เปิดไฟล์ใน `setup/github-workflows/` แล้วคัดลอกเนื้อหา → กด **Add file > Create new file** → ตั้งชื่อ `.github/workflows/<ชื่อไฟล์เดิม>` → วาง แล้วกด **Commit**
   - หรือใช้คำสั่ง `mkdir -p .github/workflows && cp setup/github-workflows/*.yml .github/workflows/` แล้ว push
2. ไปที่ **Settings > Secrets and variables > Actions**
   - แท็บ **Secrets** ใส่ `SUPABASE_ACCESS_TOKEN` (จากข้อ 1.6) และ `SUPABASE_PROJECT_REF`
   - แท็บ **Variables** ใส่ `SUPABASE_URL` และ `SUPABASE_ANON_KEY`
3. ไปที่ **Settings > Pages > Source** เลือก **GitHub Actions**
4. ไปที่แท็บ **Actions** แล้วรันทั้ง 2 workflow: **Deploy Supabase functions** และ **Deploy web (GitHub Pages)**
5. เปิด `https://<org>.github.io/<repo>/` แล้วล็อกอินด้วยบัญชีแอดมิน

### 3) เชื่อมช่องทางในหน้าเว็บ (⚙ ตั้งค่า > ช่องทาง)
แต่ละช่องทางมี: ขั้นตอนทีละข้อ · Webhook URL พร้อมปุ่มคัดลอก · ช่องกรอกค่า · ปุ่มทดสอบ (ผลทดสอบบอกสาเหตุถ้ามีปัญหา)

| ช่องทาง | สถานะ | ปุ่มช่วย |
|---|---|---|
| LINE OA | ✅ ใช้งานได้ | **ตั้ง Webhook อัตโนมัติ** (ไม่ต้องไปวาง URL เอง) |
| Facebook Messenger | ✅ ใช้งานได้ | **ผูกเพจกับแอป** |
| Instagram DM | ✅ ใช้งานได้ (ใช้ Meta App เดียวกับ Facebook) | – |
| TikTok / YouTube / Shopee / Lazada | 🕐 บันทึกค่าเตรียมไว้ได้ ตัวเชื่อมต่อมาในเฟสถัดไป | YouTube ทดสอบ API key ได้ |

> **Facebook/IG:** ต้องทำ Business Verification และส่ง App Review ก่อนใช้กับลูกค้าทั่วไป ระหว่างรออนุมัติ ทดสอบได้กับบัญชีที่มี role ในแอป ควรเริ่มยื่นเรื่องไว้ก่อนเลย เพราะใช้เวลาหลายวัน

### 4) เพิ่มพนักงาน (⚙ ตั้งค่า > พนักงาน)
เพิ่มอีเมลและรหัสผ่านให้แต่ละคน กำหนดสิทธิ์ (พนักงาน/แอดมิน) ปิดการใช้งานคนที่ลาออก และตั้งรหัสผ่านใหม่ได้ ระบบกันไม่ให้แอดมินคนสุดท้ายถูกลดสิทธิ์

### 🔒 ค่า Token เก็บที่ไหน
เก็บใน **ฐานข้อมูล Supabase ตาราง `channel_configs`** ในส่วนที่หน้าเว็บอ่านไม่ได้ เฉพาะ Edge Function เท่านั้นที่อ่านได้ เมื่อบันทึกแล้วหน้าเว็บจะแสดงแค่ว่า "ใส่แล้ว"
**ไม่เก็บ token ใน CSV หรือ Google Sheet** เพราะถ้าไฟล์หลุดหรือถูกแชร์ คนอื่นจะส่งข้อความในนามเพจ/LINE OA ของ TESR ได้ทันที
ถ้าต้องการไฟล์สำรอง ไปที่ **ตั้งค่า > ทั่วไป** ซึ่ง export การตั้งค่าและรายชื่อลูกค้าเป็น CSV ได้ (ไม่รวม secret) และเปิดใน Excel/Google Sheets ได้

## การแก้ไขภายหลัง
- แก้ไฟล์ใน `web/` แล้ว push เว็บจะอัปเดตเองภายในประมาณ 1 นาที
- แก้ไฟล์ใน `supabase/functions/` แล้ว push ฟังก์ชันจะ deploy ใหม่เอง
- แก้ไฟล์ `supabase/schema.sql` ต้องรันเองใน SQL Editor (รันซ้ำได้ ไม่ทำให้ข้อมูลหาย)

## แก้ปัญหาเบื้องต้น
| อาการ | ให้ดูที่ |
|---|---|
| ปุ่มทดสอบขึ้นแดง | อ่านข้อความใต้ชื่อช่องทาง ระบบบอกสาเหตุ (token ผิด, webhook ไม่ตรง ฯลฯ) |
| Verify webhook ไม่ผ่าน | Supabase > Edge Functions > Logs ของ `line-webhook` / `meta-webhook` · ตรวจว่ากดบันทึกและติ๊ก "เปิดใช้งาน" แล้ว |
| หน้าตั้งค่าขึ้นว่าโหลดไม่สำเร็จ | รัน `schema.sql` เวอร์ชันล่าสุดซ้ำใน SQL Editor |
| ล็อกอินได้แต่ขึ้นว่า "ไม่มีสิทธิ์" | ตั้งค่า > พนักงาน ต้องติ๊ก "ใช้งาน" |
| ส่งข้อความไม่ออก | ข้อความขึ้นกรอบแดง "ส่งไม่สำเร็จ" ให้ชี้เมาส์ดูสาเหตุ (เช่น โควตา LINE หมด หรือเกิน 24 ชม. ของ Meta) |
| ข้อความใหม่ไม่เด้งเอง | Database > Publications > `supabase_realtime` ต้องมีตาราง contacts และ messages |

## โครงสร้างไฟล์
```
├── web/
│   ├── index.html          Inbox + Dashboard + ตั้งค่า (ไฟล์เดียว)
│   └── config.js           URL/anon key (สร้างใหม่อัตโนมัติจาก repo variables)
├── supabase/
│   ├── schema.sql          ตาราง, สิทธิ์, ฟังก์ชันเวลาตอบ, ตั้งค่าช่องทาง
│   ├── config.toml
│   └── functions/
│       ├── _shared/        อ่านค่าตั้งจากฐานข้อมูล + ตัวช่วยร่วม
│       ├── line-webhook/   รับข้อความจาก LINE
│       ├── meta-webhook/   รับข้อความจาก Facebook + Instagram
│       ├── send-message/   ส่งข้อความหาลูกค้า (แยกตามช่องทาง)
│       └── admin-api/      ทดสอบการเชื่อมต่อ, ตั้ง webhook, จัดการพนักงาน
└── setup/github-workflows/ deploy เว็บ, deploy ฟังก์ชัน, กัน Supabase หลับ (คัดลอกไปที่ .github/workflows/)
```

## เพิ่มช่องทางใหม่ (สำหรับนักพัฒนา)
1. สร้าง webhook function ใหม่ใน `supabase/functions/<ชื่อ>-webhook/` ที่อ่านค่าด้วย `getChannel("<ชื่อ>")` แล้วเรียก `ingest_message`
2. เพิ่มฟังก์ชันส่งใน `SENDERS` ของ `send-message`
3. เพิ่มการทดสอบใน `testChannel` ของ `admin-api`
4. เปลี่ยน `ready: true` ใน `SETUP` ของ `web/index.html` แล้วใส่ `webhook: "<ชื่อ>-webhook"`
